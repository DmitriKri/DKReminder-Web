Creating and recurrence

Create one rule, then let it produce the right alerts.

A reminder keeps the title, schedule, and settings. An alert is one concrete notification DKReminder shows at a scheduled time. Changing one alert is not the same as changing the whole reminder rule.

Best when a catalog entry already matches the task. Open it, then review the title, time, and schedule before saving.

Step-by-step creation · Pro

Best when you want to see only the fields relevant to the current schedule.

Full editor

Best when you know the exact recurrence type and want every relevant setting on one form.

During first-run setup, creates a one-time draft for five minutes from the current time and shows the actual selected time before save.

The example below creates a weekly Saturday reminder for preparing a weekend hike. Choose a step to follow the fields in the same order in which they appear in the editor.

Start from a ready-made option

The catalog is a shortcut into the same editor, not a separate reminder type. Choose a close match, then review its title, time, and schedule.

Use the Meeting or Deadline scenario · Pro

These guided scenarios collect structured context before opening the regular reminder review. Meeting keeps participants, format, place or online platform, and preparation notes. Deadline keeps the due date, reminder cadence, destination or reference, and preparation notes.

After the scenario: review the generated title, schedule, and alert settings before saving. Without Pro, existing structured details remain visible and the ordinary reminder fields remain editable.

Choose how this reminder gets your attention

Alert mode controls how prominently this reminder tries to appear. The app-wide choice is in Settings. In an individual reminder, you can follow that choice or select a different mode just for this reminder.

Global setting

Uses the mode currently selected in Settings when the alert starts. If you later change the app-wide mode, existing reminders with this option follow the new choice.

Notifications only

Shows a regular Android notification. Sound and vibration still follow their own reminder settings.

Full-screen alert

Tries to put the reminder on the full screen. If Android cannot do that, DKReminder leaves a regular notification instead.

Based on importance

High-importance reminders try full screen. Low- and medium-importance reminders use regular notifications.

What Android permissions change

  • Notifications must be allowed. If notifications for DKReminder or its reminder channel are disabled, neither a regular notification nor the full-screen alert can be shown.
  • Full-screen access affects only full-screen display. Without it, Full-screen alert and high-importance alerts in Based on importance mode fall back to a regular notification.
  • Even with full-screen access, Android may show a prominent notification instead while you are actively using an unlocked phone.
  • Exact-alarm access affects whether an alert can arrive at the precise scheduled time; it does not change the selected alert mode.
Expected result: choose Global setting when most reminders should follow one app-wide rule. Choose another mode only when this reminder needs different behavior.

To review or restore Android access, open Notifications and Full-screen alerts.

Choose the recurrence type that matches the real rule

The recurrence type answers one question: how should DKReminder calculate the next scheduled time? Choose a calendar type when the weekday or date matters. Choose an interval when the fixed distance between alerts matters.

Once

One alert at one chosen date and time.

Every N minutes, hours, or days

A fixed interval beginning with the first trigger. These types can follow the original schedule or count from your response.

Daily, weekly, every N weeks, monthly, or yearly

A calendar rule based on selected times, weekdays, a day of the month, or an annual date.

Manual cycle · Pro

A daily sequence that begins only when you start it and then repeats inside its active window.

Similar names can produce different dates: Every 28 days is a fixed 28-day interval; Monthly follows real calendar months. Every 7 days counts from the first trigger; Weekly follows selected weekdays.

One-time reminders

Choose Once for a task that should alert at one specific date and time, such as calling a service desk tomorrow at 10:00.

  1. Select Once.
  2. Choose the date and time.
  3. Set importance and how the reminder should appear.
  4. Save and verify the scheduled time.
Expected result: DKReminder creates one scheduled alert. After that alert is resolved, the one-time reminder can move to completed reminders.

Every N minutes, hours, or days

These are three separate recurrence types with the same basic rule. Use them when the distance between alerts matters more than the calendar label.

Every 20 minutes

Useful for a short repeated routine inside an active window.

Every 3 hours

Creates scheduled points at the chosen interval. Snoozing one alert does not move the main schedule.

Every 2 days

Counts fixed day intervals from the first trigger.

Every 28 days

Still means a 28-day interval. It is not the same as monthly recurrence.

  1. Choose Every N minutes, Every N hours, or Every N days.
  2. Enter the interval and the First trigger.
  3. Optionally set an active window and an end condition.
  4. Choose whether the next alert is anchored By schedule or, with Pro, From response time.

Daily, weekly, monthly, and yearly schedules

Daily

Daily runs at one or more selected times each calendar day. It is different from Every N days: Daily follows clock times on each eligible day, while Every N days counts a fixed number of days from its first trigger.

Weekly

Weekly runs every week on one or more selected weekdays at the chosen time. Use it when the weekday itself matters, such as every Monday and Thursday.

Every N weeks

Every N weeks skips a chosen number of weeks between active weeks, then runs on the selected weekdays. The week containing the Recurrence start sets which weeks belong to the pattern.

Monthly

Monthly scheduling follows calendar months, not a fixed number of days. You can define the date in two ways.

  • On a specific day of the month. Enter the day number and alert time. If a shorter month does not have that day, the alert follows the app-wide rule or the rule selected for this reminder. Review the calendar-exception settings.
  • From the end of the month · Pro. Choose one of two options:
    • On the last day of the month. Enter the alert time.
    • A number of days before the end of the month. Enter 1–27 days and a time. The reminder alerts once on the calculated date. For example, with “4 days before,” a month ending on August 31 produces August 27, while a month ending on September 30 produces September 26. These are not daily alerts throughout the last four days.

Do not start before sets the earliest allowed date. For example, if “4 days before” is selected and the boundary is August 31, the calculated August 27 date is earlier than that boundary. The first alert is therefore September 26.

Extra alerts after that date appear only when repeat alerts without a response are enabled separately.

Yearly

Yearly recurrence uses a calendar month and date. If you select February 29, choose the explicit non-leap-year rule: February 28, March 1, or leap years only.

Schedule boundary: for Daily, Weekly, Monthly, and Yearly, Do not start before is the earliest allowed boundary. The actual alert time comes from the schedule fields.

Get advance reminders before one target date · Pro

Advance notice adds earlier alerts while keeping one main reminder date. It does not create a row of separate reminder rules: the title, checklist, history, and target date still belong to one occurrence.

Once in advance

One early alert appears at the start of the advance window. The main alert still appears on the target date.

Daily until the main reminder

An alert appears on each calendar day at the main reminder time. On the target date it is the main alert, not a duplicate early alert.

Choose a cycle-safe number of days

At least one calendar day is required. DKReminder limits the advance window so it does not overlap the neighboring recurrence cycle and make two target occurrences ambiguous.

  • One-time reminder: the first early alert must still be in the future.
  • Every N days, by schedule: at most half the interval, rounded down. For every 4 days, the maximum is 2.
  • Monthly: up to 14 days.
  • Yearly: up to 182 days.

Advance notice is available for one-time reminders, fixed Every N days, monthly schedules, and yearly schedules. It is not offered where the next target cannot be known safely in advance, such as minute/hour intervals, weekly schedules, manual cycles, or schedules counted from your response.

Respond to an early alert

  • Keep reminding me closes the current daily early alert and leaves the next planned alert.
  • Skip remaining advance reminders stops only the rest of the current occurrence’s early series; the main alert remains.
  • Got it closes a single early alert. Snooze returns that specific alert without moving the automatic schedule.
  • Done completes the current occurrence. If the reminder repeats, its next target cycle remains on schedule.
If Pro access ends: the saved advance setting remains visible, but future early alerts pause. The main reminder and its target-day alert continue. When Pro returns, early scheduling resumes from the current moment without replaying missed days.

By schedule or from response time

This choice is available for the Every N minutes, hours, and days interval types.

By schedule

An alert is planned for 10:00 and the interval is two hours. Even if you respond at 10:37, the next scheduled point remains 12:00.

From response time · Pro

You respond at 10:37, so the next alert is planned for 12:37. DKReminder waits for the response before advancing this chain.

Snooze is different. Snoozing moves the next signal for the current alert only. It does not change the reminder's recurrence schedule or create a new alert.

Manual daily cycle · Pro

Use a manual daily cycle when the day's start changes and you want later alerts to follow that real start. The cycle never starts automatically.

  1. Choose Manual daily cycle.
  2. Set the interval and inclusive active-window boundaries.
  3. Optionally enable a helper reminder that asks you to start the cycle.
  4. If the course is limited, set how many manual day starts it includes.
  5. On each day, open the reminder and choose Start when you are ready.

Example: start at 09:30 with a two-hour interval and an active window ending at 18:00. DKReminder plans 11:30, 13:30, 15:30, and 17:30. It does not add a 19:30 alert.

Course count: a ten-start course means ten manual daily starts, not ten alerts inside all cycles.

Active window and calendar exceptions

The Active window limits when new scheduled alerts may be created. Its boundaries are inclusive, and it can cross midnight, such as 22:00–06:00.

  • A planned point outside the window is not simply moved to the window start; DKReminder finds the next valid scheduled point.
  • For minute/hour intervals and a manual cycle, an invalid first calculated alert blocks saving or starting until you change the time or window.
  • An alert that already exists may be snoozed beyond the active window because snooze acts on that alert, not on the main schedule.
  • Short-month and February 29 policies appear only for the calendar edge case that needs them.

End conditions, expected result, and common checks

Repeating schedules can continue until you stop them, end after a number of scheduled alerts, or stop at a date. A manual daily cycle uses a course limit instead of the generic end condition, and a one-time reminder needs none.

Expected result: after save, the reminder summary and future preview match the recurrence type, first trigger or schedule boundary, active window, and end rule you selected.

If the schedule looks wrong

  1. Check whether you selected an interval type or a calendar type. Every 28 days is not monthly.
  2. Check the meaning of the start field: First trigger, Recurrence start, or Do not start before.
  3. For Every N weeks, verify the week that establishes the interval and the selected weekdays.
  4. For a 29th, 30th, 31st, or February 29 schedule, review the calendar exception.
  5. Check whether the active window excludes the expected point.
  6. For From response time, remember that the next alert is calculated only after you respond to the current one.
